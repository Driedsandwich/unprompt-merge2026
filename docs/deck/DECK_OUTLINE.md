## ① タイトル+タグライン

- **GYAKUMON — Intent Compiler(逆問)**
- タグライン: **「AIは、あなたの成果物を一文字も書かない。あなたの意図だけを書かせる。」**
  - 注意: 「一文字も書かない」単体の絶対表現は全資料で禁止(画面上の分岐ラベル・対照レンダ・根拠文はAI生成であり自己反証になる)。必ず「あなたの成果物を」のスコープ限定付きで統一(提出ブロッカー1)。
- サブコピー候補: 「曖昧な一文を、実行可能な意図にコンパイルする」
- 禁止語彙チェック欄(スライド化時に目視確認): 確認質問 / 明確化 / プロンプト改善 — いずれも本スライドに不在であること

## ② 問題 — 意図の空白がリビジョン地獄を生む

- 生成AIもフォームも「意図は言語化済み」と仮定する。曖昧ブリーフの空白は、読み手(人間/AI)が勝手な事前分布で埋め、**誰の意図でもない成果物**とリビジョン往復が生まれる。
- 人間は「自分が何を決めていないか」を自分では見えない。
- **生成が速くなるほど、ボトルネックは人間側=「まだ決めていないこと」へ移る。**(生成秒数の短縮曲線と、意思決定の未言語化コストの対比を1図で)
- 利用瞬間の限定を明記: 毎回使う道具ではなく、「委任コストが高いハンドオフ」の直前に使う道具(PM・発注者・個人開発者がAIや他人へ仕事を手渡す直前)。

## ③ 解 — 文がUIになる1ループ

- **1ループのみ**: 曖昧語 → その語に係留(anchor)された対照レンダリング対 → 〈決める〉か〈委ねる〉 → 原文の語が確定色/委任グレーに変わり「**この文から抽出した判断点** N→N-1」が減る。
  - カウント表記はこの限定形のみ(「未決判断点」等、意図の完全網羅を暗示する表現は禁止 — 必須変更§4)。
- **2動詞**: 操作語彙は〈決める〉〈委ねる〉のみ。〈委ねる〉は破棄ではなく「この判断はAIに委任した」という明示情報としてブリーフに残る。
- **二重憲法**:
  1. AIはユーザーの**成果物**を書かない(分岐ラベル・対照レンダ・根拠文は書く)。
  2. 人間は最初の一文以降、一度もタイプしない。残るのは選択だけ。
- 終了状態: 全語が色分けされた原文+「コンパイル済みブリーフ」(人間可読MD+機械可読JSON)。
- 脚注(袋小路への回答装備 — 必須変更§3): 〈弾く〉=「提示解釈が不適合」という情報としてブリーフに記録。カード単位の再提示はv1設計済み・P0では単純さのため封印。

## ⑥ AI統合の実体

- 反実仮想1行: **「AIを抜くと固定質問ウィザードに退化する」**。入力ごとに“下流で最も効く曖昧さ”を抽出し、その入力固有の帰結を即レンダリングする動的性にのみAIが宿る。
- 実体4点(すべて実装・実測済み):
  1. **スリム抽出**(`prompts/extraction_product_v1.txt`): 検証用フルスキーマと製品用スリムスキーマを分離。出力530〜540 tok。
  2. **anchor検証**: 各判断点の anchor_words は「原文の連続部分文字列」であることを機械検証。実在しない anchor は棄却(語テザー破綻の構造的防止)。実測: **22実行で anchor違反0・対照ブリーフでの分岐捏造0・エラー0**(v1+v2キラーテスト)。
  3. **可視タクソノミー**: 抽出プロンプトはリポジトリ内の可視ファイル。審査員が直接読める。プロンプト1行の改変で挙動が変わる(決勝Live Prototypingの改変対象)。
  4. **エンジン実測値**: 初期構成 api 97〜123秒 → 最終構成 api 8.8〜15秒+起動オーバーヘッド約1秒(4段階の工学決定。詳細は⑦)。
- 低曖昧ブリーフでの品質例: precise-pricing でスリム版が発見した4分岐は全て原文の実在ギャップに基づく(捏造の対極)。
