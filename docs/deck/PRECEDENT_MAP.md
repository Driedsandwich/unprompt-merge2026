# PRECEDENT_MAP — 先行事例マップ(デック⑤の原稿)

下書き: 2026-07-29。1枚図として Day3 にスライド化。

## 軸の定義

- **横軸: 質問様式** — 逐次テキスト(1問ずつ言葉で聞く)⇔ 並列帰結レンダ(複数の解釈の帰結を同時に見せて選ばせる)
- **縦軸: AIの成果物執筆** — する(AIがユーザーの成果物そのものを書く/作る)⇔ しない(AIは成果物を書かず、意図の構造化までで止まる)

```
                 AIが成果物を書く
                        ▲
   ChatGPT確認質問      │      Midjourney変種選択
   Deep Researchプラン確認│
   (プロンプト改善ツール) │
────────────────────────┼────────────────────────
 逐次テキスト ◀─────────┼─────────▶ 並列帰結レンダ
                        │
   mattpocock grill-me  │      ★ GYAKUMON(空白象限)
                        │
                        ▼
                 AIは成果物を書かない
```

## 配置と事実根拠(各一行)

| 事例 | 質問様式 | 成果物執筆 | 一行の事実根拠 | 確認状態 |
|---|---|---|---|---|
| ChatGPT 確認質問 | 逐次テキスト | する | 曖昧な依頼に対し言葉で聞き返した後、AI自身が成果物を生成する(「温かみ=色か口調か」と言葉で聞かれても、言語化済みでない意図は選べない) | 公知の挙動。Day3にスクリーンショットで一次確認予定 |
| Deep Research 型プラン確認 | 逐次テキスト(プラン提示→承認) | する | 調査開始前に計画をテキストで確認させるが、最終レポートはAIが全文執筆する | 公知の挙動。Day3にスクリーンショットで一次確認予定 |
| プロンプト改善ツール | 逐次テキスト | (下流のAIが)する | 文面の言い回しを直すだけで、ユーザーがまだ決めていない意図を発見させない | 公知のカテゴリ挙動(特定製品名は挙げない) |
| Midjourney 変種選択 | 並列帰結レンダ(4枚グリッド) | する | 帰結を並列画像で選ばせる様式は実証済みだが、その画像自体がAI執筆の成果物であり、意図の構造化データは残らない | 公知の挙動。Day3にスクリーンショットで一次確認予定 |
| mattpocock「grill-me / grilling」(2026-03頃公開) | 逐次テキスト(1問ずつ) | しない(成果物定義なし) | 生成前にAIが徹底的に問うスキルだが、1問ずつ逐次・テキスト問答で、終点は共有理解(構造化された成果物定義を出力しない)。しかも同スキル自身が「複数質問の同時提示は混乱させる(bewildering)」と明記 | **一次確認済み**(2026-07-29、FINAL_DECISION.md 追記に記録) |
| **GYAKUMON** | **並列帰結レンダ** | **しない** | 語アンカー×帰結レンダリング×成果物不執筆の交点。終点は「コンパイル済みブリーフ」(決定・委任・根拠のMD+JSON) | 本提出物 |

## 使い方(語りの一行)

- grilling の存在は**需要の実証**であり、その自認(「複数質問の同時提示は混乱」)は**本作の存在理由の傍証**である: テキストでは混乱する並列を、帰結レンダリングは可能にする。
- 回答様式も逆: grilling=AIが推奨答を書き、人が読む / GYAKUMON=人は読まず選ぶ(タイプゼロ)。
- Midjourney は「並列帰結選択のUXが機能する」ことの実証であり、GYAKUMON はそれを「成果物を書かない側」の象限へ移した。

## 注意(誠実性)

- 「空白象限」は本マップの2軸上の主張であり、全製品空間の網羅を主張しない(スライドの脚注に明記)。
- grill-me 以外の各事例は公知の挙動として記載しており、スライド化前(Day3)に現行UIのスクリーンショットで一次確認し、確認日を脚注に付す。挙動が変わっていた場合は記載を実態に合わせて修正する。
