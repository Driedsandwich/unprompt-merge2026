# Unprompt — Intent Compiler

旧称/コードネーム: GYAKUMON(逆問)。対外名は Unprompt、リポジトリ/ディレクトリ名 `gyakumon/` と審議記録・機械マーカーは旧称のまま(二層命名。docs/DISCLOSURE.md #19)。

曖昧な制作ブリーフを「後戻りコストの高い判断点(分岐)」に逆コンパイルし、選択肢つきで発注者に問い返すインテント・コンパイラ。

MERGE 2026 AI Designathon 提出用プロダクト。本ディレクトリは Day1 成果物「キラーテスト・ハーネス」(抽出品質をブラウザで実測する装置)。

```
gyakumon/
├── README.md              … 本ファイル
├── COMMANDS.md            … ユーザーが実行するコマンド集
├── PROCESS_LOG.md         … AI提案と人間判断のログ(3列表)
├── killer_test/
│   └── index.html         … キラーテスト・ハーネス本体(単一HTML、ビルドレス)

├── data/
```

## 実行方法

ビルド不要。npm / Node / バンドラは使わない。

killer_test/ の中ではなく、その親である gyakumon/ ディレクトリで起動する:

```sh
cd <このREADMEがある gyakumon/ ディレクトリ>
python3 -m http.server 8000
```

ブラウザで http://localhost:8000/killer_test/index.html を開く。

**注意: killer_test/ 内で http.server を起動しないこと。** `../prompts/` と `../data/` がサーバルート外を指して 404 になり、ハーネスが「読込エラー」で止まる。

**注意: `file://` で index.html を直接開かないこと。** ハーネスは `../prompts/extraction_v0.txt` と `../data/briefs.json` を `fetch()` で読み込むため、`file://` 直開きではブラウザのセキュリティ制約により fetch が失敗しうる。必ず `python3 -m http.server` 経由で配信する。

## APIキー

- 画面の password 入力欄に Anthropic API キーを入力する。sessionStorage にのみ保存(タブを閉じると消える)。
- キーをコードやリポジトリに書かない。
- ブラウザから Anthropic Messages API を直接呼ぶ(`anthropic-dangerous-direct-browser-access: true`)。自分のキーを自分のブラウザで使う前提の検証用構成。

## キラーテストの手順

1. サーバを起動しハーネスを開く(上記)。
2. APIキーを入力、モデルを選択(既定: claude-sonnet-5 / 代替: claude-fable-5)。
3. ブリーフ11本(曖昧10本 + 完全指定の対照1本、各曖昧ブリーフには対照ペアあり)を順に送信する(個別または一括)。
4. ハーネスは各応答について機械判定を表示する:
   - anchor_words が原文の連続部分文字列として実在するか
   - 分岐数・選択肢数がスキーマ制約内か
   - 送信→初回応答レイテンシ(合格線: 8秒以内)
   - 対照(完全指定)ブリーフで分岐を捏造していないか
5. 分岐の「有効性」(その判断点が本当に成果物を左右するか)の意味判定は人間(管制塔)が画面上で行う。

### 合格線

- 曖昧ブリーフ10本中8本で有効分岐率 70% 以上
- anchor_words がすべて原文に実在
- 各ブリーフに対照ペア1組以上
- 送信→初回応答 8秒以内
- 対照(完全指定)ブリーフで分岐を捏造しないこと

注: 本ハーネスは非ストリーミングのため、計測する ttfb_ms(送信→初回応答)は応答完了(全生成)時刻とほぼ同値であり、CORS プリフライト往復も含む。8秒線はこの保守的な定義で判定される。

## Unprompt 本体(Intent Compiler)

曖昧ブリーフを送信すると、生成の代わりに文が判断点カードへ爆散し、帰結を選ぶだけで意図が明示ブリーフへコンパイルされる。killer_test/ が抽出品質の検証装置だったのに対し、こちらが製品本体。

### 構成(本体)

```
gyakumon/
├── server.py               … ローカルAPIサーバ(python3標準ライブラリのみ、127.0.0.1限定)
├── app/
│   └── index.html           … 単一ファイル・バニラJSのフロントエンド
├── prompts/
│   ├── extraction_v0.txt    … 抽出プロンプト(既存・変更禁止)
│   ├── render_v0.txt        … ミニレンダ用トークン生成プロンプト
│   └── compile_v0.txt       … コンパイル根拠文生成プロンプト
└── logs/
    └── session_<起動時刻>.jsonl … 全API呼び出しの証拠ログ
```

### 起動方法

エンジンは Claude Code サブスクリプションのヘッドレスCLI(`claude -p ... --output-format json`)。Anthropic APIキーは不要(claude CLI にログイン済みであること)。

```sh
cd <このREADMEがある gyakumon/ ディレクトリ>
python3 server.py
```

ブラウザで **http://127.0.0.1:8321/** を開く。

server.py は静的ファイル(app/ 配下)を `/` で配信しつつ、`/api/explode` `/api/explode_stream` `/api/render` `/api/compile` `/api/health` を提供する。localhost 以外へはバインドしない。

`/api/explode_stream` は `/api/explode` と同じ抽出を SSE(`text/event-stream`)で逐次配信する経路である。claude を `--output-format stream-json --include-partial-messages` で走らせ、生成中のJSONを増分パースして、**分岐1件ぶんのオブジェクトが閉じた時点で** anchor 検証を通してから1件ずつ送る。ブラウザはこれを使い、最初の1件が届いた時点で爆散を始める。ストリームが1枚も出せずに失敗した場合だけ、自動で `/api/explode`(従来の一括経路)へ戻る。

### ゴールデンパス(操作手順)

1. **初期画面**: 見慣れたプロンプト箱だけ。ブリーフ文を入力して送信する。人間がタイプするのはこの最初の一文のみ(以降タイプしない)。
2. **静寂**: 送信直後、生成は始まらない。0.1秒刻みの経過秒カウンタと極小文字「x1.0 — 生成は、始まらない」が表示される。これは演出ではなく実測時間そのもの。静寂が止まるのは**最初の判断点が確定した瞬間**であり、表示される秒数は「送信→最初のカード」の実測値である。
3. **爆散**: 文が語スパンに分解され、各判断点カードが anchor 語と SVG テザー線で結ばれて周囲に配置される(このアニメーションは1回のみ)。カードは最大5枚、ミニレンダはトークン到着まではスケルトン表示(白紙禁止)。カードは抽出が終わるのを待たず、**確定した判断点から1枚ずつ**現れる。全件が出そろうまでカウンタは「判断点を抽出中… N」と表示し、総数が確定してから「この文から抽出した判断点 N→0」に切り替わる(まだ増えうる数を確定値として見せない)。既に置いたカードは後続の到着で動かない。
4. **カード操作(二動詞のみ)**:
   - **決める**: カードのミニレンダをクリックして選択肢を確定 → 語が確定色(藍系)になる。
   - **委ねる**: カードの「委ねる」ボタンを押す → 語が委任グレーになる。
   - 確定/委任済みの語を再クリックすると同じカードが再提示され、選び直せる(状態上書き、多段アンドゥなし)。
   - 画面上部のカウンタ「この文から抽出した判断点 N→0」が操作のたびに減っていく。
5. **コンパイル**: N が 0 になるとコンパイルボタンが現れる。押すとコンパイル画面に遷移し、人間可読MDと機械可読JSONを切り替えて閲覧できる。非対称カウンタ「あなたがタイプした文字: 0 / あなたの選択: N」が表示され、各判断点の根拠文は `/api/compile` の応答から埋め込まれる。

### 証拠ログの場所

すべてのAPI呼び出し(`/api/explode` `/api/explode_stream` `/api/render` `/api/compile`)は `logs/session_<起動時刻>.jsonl` に1行1呼び出しで追記される。各行は `{ts, endpoint, model, wall_ms, api_ms, ok}` を含む。サーバ起動ごとに新しいファイルが作られる(既存ファイルへの上書きなし)。
