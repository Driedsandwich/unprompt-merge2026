# Gate 1 裁定(管制塔・2026-07-29)

## 裁定: 主経路続行(GYAKUMON 続行・ヒラク切替なし・フォールバック1不要)

## 根拠

### 品質(合格線: 10本中8本で有効分岐率70%以上) — 明確に PASS

- v1(フルスキーマ・検証用)+ v2(スリム・製品形状)の計22実行で **anchor違反 0 / 対照ブリーフでの捏造 0**
- 意味判定(管制塔・敵対基準): v1完走4ブリーフ=有効率実質100%、v2抜き取り3ブリーフ(precise-pricing / scout-mail / internal-deck)=全分岐が「埋め方次第で成果物が本質的に分かれる」判断点で、独立性・正直な既定値(情報不足時は「空欄プレースホルダー」)も確認
- 特筆: 低曖昧ブリーフ precise-pricing でスリム版が発見した4分岐(想定読者の分割軸・Pro誘導強度・年払い表示・課金開始条件)は全て原文の実在ギャップに基づく — 捏造の対極
- 切替条件A(「フォールバックでも同型カード集合が並ぶ=AI統合の物語崩壊」)は**不成立**

### レイテンシ — 工学的に解決(2段階)

| 構成 | 実測 |
|---|---|
| 初期(--append-system-prompt・effort既定・リッチスキーマ) | api 97〜123秒 / 出力8〜10K tok / タイムアウト6本 |
| --system-prompt置換 + --effort low | api 44.5秒 / 2.7K tok |
| + スリムスキーマ(extraction_product_v1.txt) | api 8.8〜15秒 / 530〜540 tok |
| + --setting-sources project(起動オーバーヘッド遮断) | 壁時計 ≈ api + 約1秒(従来+13〜27秒) |

- 単発呼び出しの現実値: **壁時計 9〜16秒**。厳格8秒線(単発)は未達
- 製品対応(Day 2 実装): `--output-format stream-json` による**分岐ストリーミング**で初回カード表示を8秒以内へ(サーバがSSEで分岐単位に逐次配信)。動画・デモの「静寂」演出は実測値ベースで絵コンテを更新する(誠実性プロトコル)
- 8秒線の定義は「送信→初回操作可能」であり、ストリーミング初回カードで判定する(単発完了時間ではない)。この解釈変更を開示リストに記録

### プロンプト改訂の消費

- v0(検証用フル)→ product_v1(製品用スリム): 1回目。残り1回

## ヒラク(Runner-up)の扱い

切替条件Aが不成立のため bbox キラーテストは実施しない(リソースを Champion に集中)。ヒラクは審議時の設計のまま書面上の Runner-up として保持。

## エンジン標準構成(以後の全呼び出しで使用)

```
claude -p <user_prompt(-- の後ろ)> \
  --system-prompt <プロンプトファイル全文> \
  --strict-mcp-config --setting-sources project --effort low \
  --model sonnet --output-format json(または stream-json) \
  cwd=リポジトリ外一時ディレクトリ
```
